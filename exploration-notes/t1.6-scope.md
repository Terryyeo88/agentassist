# T1.6 Orchestration Chain — Scope & Design

**Branch:** `t1.6-orchestration-chain`  
**Date:** 2026-05-31  
**Status:** Scoping / pre-implementation

---

## 1. Purpose and Scope

T1.6 replaces Claude's conversational tool selection — where the LLM decides at runtime which MCP tools to call and in what order — with a deterministic six-step chain that is hard-coded, sequenced, and gated. Each step has fixed inputs and outputs; progression is conditional on arithmetic and set-membership reconciliation rules, never on an LLM judgment call. This predictability is the defensibility feature: for a regulated GST audit workflow, "Claude decided to skip validate_invoice_tax_codes" is an unacceptable failure mode; "Gate 3 halted at 09:14:02 with message X" is auditable.

**Out of scope (T1.6):**
- Dynamic subtask selection (chain topology is fixed)
- Retry / backoff inside the chain (deferred to T2.4)
- Multi-agent message passing (single-process orchestrator)

## 2. Chain Steps

### Step a — Fetch

**Purpose:** Pull all invoices, purchase invoices, credit notes, and purchase credit notes for the period from SAP B1. Establishes the single source of truth for what was examined.

**Inputs:**
```python
class FetchInput(TypedDict):
    client_config: ClientConfig   # from T1.3
    period: Period                # {start: "YYYY-MM-DD", end: "YYYY-MM-DD"}
```

**Outputs:**
```python
class InvoiceRecord(TypedDict):
    doc_num: int
    doc_date: str                 # "YYYY-MM-DD"
    doc_type: Literal[
        "sales_invoice", "purchase_invoice",
        "sales_credit_note", "purchase_credit_note"
    ]
    doc_currency: str
    doc_total: float
    card_name: str
    vat_group: str

class FetchManifest(TypedDict):
    period: Period
    fetched_at: str               # ISO datetime, for audit trail (T1.5)
    records: list[InvoiceRecord]  # all four doc types, flat list
    doc_nums: set[int]            # O(1) lookup used by Gate 4
    sap_inline_count: int | None  # from OData $inlinecount; None if unavailable
```

**MCP tool:** None — direct SAP B1 OData calls.  
**Claude invoked:** No.  
**Parallelizable:** No — all subsequent steps depend on this output.

### Step b — Classify

**Purpose:** Invoke `validate_invoice_tax_codes` to audit VatGroup assignments across the fetched documents.

**Inputs:** `FetchManifest.records`, `period`

**Outputs** (verbatim tool output schema):
```python
class VatGroupEntry(TypedDict):
    gst_category: str
    side: Literal["sales", "purchase", "unknown"]
    lt_box: str | None
    tt_box: str | None
    doc_count: int
    known_to_mapping: bool

class ClassifyIssue(TypedDict):
    doc_num: int
    doc_date: str
    doc_currency: str
    card_name: str
    vat_group: str
    line_total: float
    tax_total: float
    error_code: Literal["E1", "E2", "E3", "E4"]
    description: str

class ClassifyOutput(TypedDict):
    period: Period
    expected_rate: float          # 0.07 or 0.09
    vatgroup_inventory: dict[str, VatGroupEntry]
    issues: list[ClassifyIssue]
    summary: dict[str, int]       # keys: E1, E2, E3, E4, total
```

**MCP tool:** `validate_invoice_tax_codes`  
**Claude invoked:** Yes — with tax-code classification KB slice only.  
**Parallelizable:** Yes — parallel with Calculate and Detect (all three consume `FetchManifest`).

### Step c — Calculate

**Purpose:** Invoke `calculate_f5_return` to compute all eight GST return boxes and surface E1 candidates and anomalies.

**Inputs:** `FetchManifest.records`, `period`

**Outputs** (verbatim tool output schema):
```python
class FxInvoice(TypedDict):
    doc_num: int
    doc_date: str
    currency: str
    doc_total: float
    card_name: str
    type: Literal["sales", "purchase", "sales_credit_note", "purchase_credit_note"]

class E1Candidate(TypedDict):
    doc_num: int
    doc_date: str
    card_name: str
    doc_currency: str
    vat_group: Literal["SO", "DS"]

class CreditNoteApplied(TypedDict):
    doc_num: int
    doc_date: str
    card_name: str
    type: Literal["sales_credit_note", "purchase_credit_note"]
    vat_group: str
    line_total_applied: float     # negative
    tax_total_applied: float      # negative

class Anomaly(TypedDict):
    doc_num: int
    issue: str

class F5ReturnOutput(TypedDict):
    period: Period
    currency: Literal["SGD"]
    boxes: dict[str, float]       # box_1 through box_8
    fx_invoices_requiring_conversion: list[FxInvoice]
    e1_candidates: list[E1Candidate]
    record_counts: dict[str, int]
    credit_note_counts: dict[str, int]
    credit_notes_applied: list[CreditNoteApplied]
    anomalies: list[Anomaly]
```

**MCP tool:** `calculate_f5_return`  
**Claude invoked:** Yes — with F5-calculation KB slice only.  
**Parallelizable:** Yes — parallel with Classify and Detect.

### Step d — Detect

**Purpose:** Invoke `detect_gst_errors` to produce severity-ranked issue list covering E1–E4, NO_GST_REG, and COMPLETENESS signals.

**Inputs:** `FetchManifest.records`, `period`

**Outputs** (verbatim tool output schema):
```python
class DetectIssue(TypedDict):
    severity: Literal["HIGH", "MEDIUM", "LOW"]
    error_code: Literal["E1", "E2", "E3", "E4", "NO_GST_REG", "COMPLETENESS"]
    doc_num: int | None           # None for COMPLETENESS
    doc_date: str | None
    card_name: str | None
    description: str
    recommendation: str

class DetectOutput(TypedDict):
    period: Period
    severity_counts: dict[str, int]   # HIGH, MEDIUM, LOW
    issues: list[DetectIssue]
```

**MCP tool:** `detect_gst_errors`  
**Claude invoked:** Yes — with error-detection KB slice only.  
**Parallelizable:** Yes — parallel with Classify and Calculate.

---

### Step e — Compile

**Purpose:** Aggregate outputs from b/c/d into one structured object. Deduplicates anomalies, cross-checks E1 candidates, resolves `NO_GST_REG` dedup, and attaches the fetch manifest as the "items examined" record for the report.

**Inputs:** `FetchManifest`, `ClassifyOutput`, `F5ReturnOutput`, `DetectOutput`

**Outputs:**
```python
class E1Reconciliation(TypedDict):
    calc_doc_nums: set[int]       # from F5ReturnOutput.e1_candidates
    detect_doc_nums: set[int]     # from DetectOutput where error_code == "E1"
    matched: bool                 # True iff sets are equal

class CompileOutput(TypedDict):
    period: Period
    fetch_manifest: FetchManifest
    calculate: F5ReturnOutput
    classify: ClassifyOutput
    detect: DetectOutput
    deduplicated_anomalies: list[Anomaly]   # union of calc anomalies + classify unknowns
    e1_reconciliation: E1Reconciliation
    surfaced_warnings: list[str]            # Gate-level warnings preserved for report
```

**MCP tool:** None.  
**Claude invoked:** No — pure Python aggregation.  
**Parallelizable:** No — sequential after b/c/d.

---

### Step f — Report-input

**Purpose:** Shape `CompileOutput` into the flat structured dict that T1.4's PDF renderer consumes. Terminal output of the chain.

**Inputs:** `CompileOutput`

**Outputs:**
```python
class ReportInput(TypedDict):
    period: Period
    boxes: dict[str, float]
    issues: list[ClassifyIssue | DetectIssue]   # merged, sorted by severity then doc_num
    e1_candidates: list[E1Candidate]
    anomalies: list[Anomaly]
    warnings: list[str]
    items_examined: dict[str, int]   # doc-type → count, from FetchManifest
    generated_at: str                # ISO datetime
```

**MCP tool:** None.  
**Claude invoked:** No.  
**Parallelizable:** No — sequential after e.

> **Note:** The exact `ReportInput` shape will be reconciled with T1.4's renderer interface before implementation. The above is the minimum required by the sections visible in T1.4.

## 3. Deterministic Gates

All gates are pure arithmetic or set-membership checks. `GateFailure` is raised on any failing assertion; the chain halts immediately and the message is printed to stdout/logged.

---

### Gate 1 — After Fetch: Record-count sanity

```python
def gate_1_record_count(manifest: FetchManifest) -> None:
    if manifest.sap_inline_count is None:
        log.warning("Gate 1 [record-count]: SAP $inlinecount unavailable — cannot verify pagination completeness")
        return
    actual = len(manifest.records)
    if actual != manifest.sap_inline_count:
        raise GateFailure(
            f"Gate 1 [record-count]: SAP reported {manifest.sap_inline_count} records, "
            f"fetched {actual} — possible truncated pagination"
        )
```

**Catches:** OData pagination truncation (e.g. missing `$skip` increment on large result sets).

---

### Gate 2 — After Calculate: Box reconciliation

```python
def gate_2_box_reconciliation(calc: F5ReturnOutput) -> None:
    b = calc["boxes"]
    TOLERANCE = 0.01

    box4_expected = b["box_1_standard_rated_sales"] + b["box_2_zero_rated_sales"] + b["box_3_exempt_sales"]
    if abs(b["box_4_total_sales"] - box4_expected) > TOLERANCE:
        raise GateFailure(
            f"Gate 2 [box-4]: box_4={b['box_4_total_sales']:.2f} != "
            f"box_1+box_2+box_3={box4_expected:.2f} (delta={abs(b['box_4_total_sales'] - box4_expected):.4f})"
        )

    box8_expected = b["box_6_output_tax"] - b["box_7_input_tax"]
    if abs(b["box_8_net_gst"] - box8_expected) > TOLERANCE:
        raise GateFailure(
            f"Gate 2 [box-8]: box_8={b['box_8_net_gst']:.2f} != "
            f"box_6-box_7={box8_expected:.2f} (delta={abs(b['box_8_net_gst'] - box8_expected):.4f})"
        )

    for anomaly in calc["anomalies"]:
        log.warning(f"Gate 2 [anomaly]: doc_num={anomaly['doc_num']} — {anomaly['issue']}")
        # Not a halt; compile step must preserve these in surfaced_warnings
```

---

### Gate 3 — After Classify: Inventory consistency

```python
def gate_3_inventory_consistency(classify: ClassifyOutput) -> None:
    if classify["summary"]["total"] != len(classify["issues"]):
        raise GateFailure(
            f"Gate 3 [summary-count]: summary.total={classify['summary']['total']} "
            f"!= len(issues)={len(classify['issues'])}"
        )

    inventory_keys = set(classify["vatgroup_inventory"].keys())
    for issue in classify["issues"]:
        if issue["vat_group"] not in inventory_keys:
            raise GateFailure(
                f"Gate 3 [vg-reference]: issue doc_num={issue['doc_num']} "
                f"references vat_group='{issue['vat_group']}' not present in vatgroup_inventory"
            )

    for vg, entry in classify["vatgroup_inventory"].items():
        if not entry["known_to_mapping"]:
            log.warning(f"Gate 3 [unknown-vg]: '{vg}' not in mapping — compile must surface as anomaly")
```

---

### Gate 4 — After Detect: Severity-count and DocNum-reference consistency

```python
def gate_4_detect_consistency(detect: DetectOutput, manifest: FetchManifest) -> None:
    count_sum = sum(detect["severity_counts"].values())
    if count_sum != len(detect["issues"]):
        raise GateFailure(
            f"Gate 4 [severity-count]: sum(severity_counts)={count_sum} "
            f"!= len(issues)={len(detect['issues'])}"
        )

    for issue in detect["issues"]:
        if issue["doc_num"] is not None and issue["doc_num"] not in manifest.doc_nums:
            raise GateFailure(
                f"Gate 4 [dangling-ref]: detect issue references doc_num={issue['doc_num']} "
                f"which does not appear in fetched dataset (error_code={issue['error_code']})"
            )
```

---

### Gate 5 — After Compile: Cross-tool consistency

```python
def gate_5_cross_tool_consistency(
    calc: F5ReturnOutput,
    classify: ClassifyOutput,
    detect: DetectOutput,
) -> None:
    # E1 set equality: calculate.e1_candidates vs detect issues with error_code "E1"
    calc_e1 = {c["doc_num"] for c in calc["e1_candidates"]}
    detect_e1 = {i["doc_num"] for i in detect["issues"] if i["error_code"] == "E1"}
    if calc_e1 != detect_e1:
        raise GateFailure(
            f"Gate 5 [E1-set]: calculate E1 doc_nums={sorted(calc_e1)} "
            f"!= detect E1 doc_nums={sorted(detect_e1)} "
            f"(only-in-calc={sorted(calc_e1 - detect_e1)}, only-in-detect={sorted(detect_e1 - calc_e1)})"
        )

    # Unknown VatGroup agreement: calc anomaly strings vs classify inventory flags
    calc_unknown_vgs: set[str] = set()
    for a in calc["anomalies"]:
        if "unknown VatGroup" in a["issue"]:
            # issue format: "unknown VatGroup 'XYZ' — not in mapping"
            try:
                calc_unknown_vgs.add(a["issue"].split("'")[1])
            except IndexError:
                pass  # malformed — logged, not halted

    classify_unknown_vgs = {
        vg for vg, entry in classify["vatgroup_inventory"].items()
        if not entry["known_to_mapping"]
    }

    unmatched = calc_unknown_vgs - classify_unknown_vgs
    if unmatched:
        raise GateFailure(
            f"Gate 5 [vg-unknown]: calculate references unknown VatGroups "
            f"not flagged by classify: {sorted(unmatched)}"
        )
```

## 4. File Structure

```
orchestrator/
    __init__.py
    chain.py        # run_chain(client_config, period) → ReportInput
    steps.py        # fetch(), classify(), calculate(), detect(), compile(), report_input()
    gates.py        # gate_1() … gate_5(), each raises GateFailure
    schemas.py      # TypedDicts: FetchManifest, CompileOutput, ReportInput, etc.
    exceptions.py   # GateFailure(Exception), ChainError(Exception)

run_agent.py        # T1.3 launcher, extended to call run_chain()
```

**Rationale:** `chain.py` owns the sequence and gate-call order — it is the only file that knows the topology. `steps.py` and `gates.py` are independently testable with no imports between them. `schemas.py` is the single source of truth for inter-step data shapes; any step or gate can import from it without circular dependencies. `exceptions.py` is isolated so `gates.py` can raise and `chain.py` can catch without a shared utils import.

`orchestrator/` does **not** import from `scripts/run_baseline_tests.py`. The baseline tests are an independent audit path; the chain must not silently depend on or interfere with them.

## 5. Minimum Viable T1.6 — Definition of Done

One command:
```bash
python run_agent.py --client SBODEMOSG --period 2024-07-01 2024-09-30
```

Must:
1. Load `SBODEMOSG` client config via T1.3 loader
2. Run all six chain steps for Q3 2024
3. Check all five gates in order; halt with a human-readable `GateFailure` message on any failure
4. Produce one aggregated output file:
   ```
   exploration-notes/t1.6-tool-outputs/chain-run-<YYYYMMDD-HHMMSS>.json
   ```
   *(Path is provisional — will be aligned with T1.5 audit trail when Collin's work lands)*
5. Each Claude invocation in steps b/c/d receives only its step's designated KB slice (modular KB guardrail — no cross-step KB bleed)

**Acceptance test:**

Hand-edit a fetched record so `box_4_total_sales` no longer equals `box_1 + box_2 + box_3`. Re-run. The chain must halt at Gate 2 with a message containing the delta and the word "box-4" — it must not produce output.

## 7. Open Questions for Terry's Decision

1. **Detect inputs:** Does `detect_gst_errors` receive the raw fetched records (parallel-safe), or does it require `ClassifyOutput` or `F5ReturnOutput` as additional context? The roadmap says parallel-safe, implying fetch-only inputs — but if the MCP tool's implementation consults classify output internally, serial ordering may be required.

2. **ReportInput exact shape:** T1.4's renderer has an existing interface. Before implementing Step f, the `ReportInput` TypedDict should be validated against the renderer's actual call site to avoid a shape mismatch.

3. **Gate 5 VatGroup parsing:** The cross-check parses VatGroup codes from `calculate_f5_return.anomalies[].issue` strings (format: `"unknown VatGroup 'XYZ' — ..."`). If `calculate_f5_return` ever changes its issue string format, Gate 5 silently degrades. Consider whether `calculate_f5_return` should expose an `unknown_vat_groups: list[str]` field directly.

4. **KB slice ownership:** The three KB slices (classify / calculate / detect) are referenced here but not yet defined. Which KB documents belong to each slice needs to be specified before writing the Claude prompts for steps b/c/d.
